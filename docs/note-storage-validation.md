# 首篇笔记保存与重开验证

日期：2026-10-14。对应 [#14：在可用笔记库创建、保存并重开首篇笔记](https://github.com/HoboCY/CueNote/issues/14)。本记录只覆盖该任务；#12 是汇总全部开发与验收任务的父任务。

## 实现范围

当前版本提供默认或自选笔记库、默认笔记本、标题与康奈尔三分区纯文字编辑、手动保存及重开。Rust 管理完整 v1 笔记包、资产、身份和版本基线；浏览器预览不模拟保存。已知富内容暂只读，自动保存与关闭保护由 #15 继续实现。

实现契约见 [note-storage-contract.md](note-storage-contract.md)。审查基线为 `9c4f5d2c414a23f9ccd86cc6637992531fc36f61`。

测试日志中的 `ZipWriter::drop ... package exceeds 256 MiB` 来自故意超限的拒绝用例。ts-rs 对 serde `deny_unknown_fields` 的警告仅表示 TypeScript 生成器不处理该校验属性；Rust 的未知字段拒绝未被移除，JSON Schema 和原生验证仍分别执行各自检查。

## Standards

固定树 `908c1201e6123b21dd18c274f7623c0993c2fbbd` 的独立审查未发现项目文档的硬性违规，提出两项判断性发现：

- P2：恢复草稿复制/新建只同步文件，缺少 Unix 目录同步。已在 `8e341076aed7c046259b75ddc1bdb6735f578753` 中补齐目录链同步和失败说明，独立复核确认解决。Unix/macOS 实机结果仍未验证。
- P3：笔记格式与笔记本元数据各自实现 UUID v4 和毫秒 UTC 校验。当前规则一致，保留为后续维护时需要同时核对的非阻断风险；本次未为此增加额外模块。

## Spec

同一固定树的独立 #14 规格审查发现 P2：Unix 原子创建使用硬链接，目录探针却只验证普通创建及原子替换。`8e341076aed7c046259b75ddc1bdb6735f578753` 已让探针复用正式无覆盖创建原语，独立复核确认该问题解决。

复核又指出探针失败后不能删除未确认由本次创建的路径。最终审查树 `c334cd02e7c2be4399e835901842e4283d7de126` 只清理已记录且内容未变化的探针文件；碰撞目标、部分写入及不确定结果会保留并报告。新增回归确认无覆盖发布撞上已有目标时不会删除该目标。两个审查轴均已复核该修正，未发现新的实质问题。

审查汇总：Standards 初审 2 项，其中 P2 已解决，P3 为保留的非阻断维护风险；Spec 共 2 项 P2 均已解决，无未解决的规格发现。

## 验收边界

Windows 执行器曾在受限环境下拒绝文件替换；在真实权限环境用隔离目录复验通过。没有修改用户目录的加密或权限，也没有增加直接覆盖退路。这不能推断所有目录都支持安全保存，选择目录时仍执行探针，每次保存仍处理实际失败。

本次不证明 macOS、真实 OneDrive 双端、安装包、千篇库性能、完整富文本编辑、自动保存或完整故障恢复通过。对应任务完成前，不能把当前版本视为首版日用验收完成。
