## 开发顺序

先贯通真实桌面启动，再完成“选择笔记库 → 三分区写字 → 安全保存 → 重开”的最小完整流程。随后自动保存、组织和编辑能力可沿不同任务推进；每项功能从界面到原生文件往返可演示。保存安全随最初可写版本交付，不留到最后补。

T01 完成后开始 T02；T02 完成后 T03 与 T06 可并行，T03 完成后开放多笔记导航及打包准备。并行前仍需分配文件所有权；依赖图不代表可以同时编辑同一文件。T20 可在基本可写流程稳定后提前准备安装包，不等到功能全部完成才发现打包问题。T21 需要两台实机及用户配合，不把本机构建或模拟同步当成完成。

## 模块与目录

采用单应用工程；只有存在真实行为才建模块，不预建大量空目录。

- 根目录负责前端构建配置、锁文件和开发入口；
- src/ 承载 React 应用与真实宿主接口，后续按笔记会话、编辑内容、笔记库导航等行为拆分；
- src-tauri/ 承载 Rust 宿主、受限命令及文件/库行为，文件读写规则集中封装；
- docs/ 保留术语、ADR、开发入口及验收证据指引，权威产品规则引用 GitHub 决策；
- 后续 schema/固定样本在 T02 实际落地，编辑器允许节点与原生文件校验共用版本约定；
- 本机索引、恢复区和备份不进入事实同步目录；开发生成文件不纳入版本管理。

正式工程从 origin/main 创建 codex/project-foundation 分支，保留已有本地文档。原型目录继续独立，不整包复制进正式实现。
