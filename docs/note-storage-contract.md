# 首篇笔记实现契约（#14）

依据已批准的 [#14](https://github.com/HoboCY/CueNote/issues/14)、[架构](https://github.com/HoboCY/CueNote/issues/7#issuecomment-6164489548)和[最终验收规格](https://github.com/HoboCY/CueNote/issues/8#issuecomment-6165724793)。本文件记录实现细节，不改变用户可见范围。

## 已确认的测试范围

沿用 #14 第 4–6 项验收条件已经批准的接口行为：

- 原生笔记格式的读写接口：固定有效/无效样本、完整结构往返、未知格式和资源上限拒绝。它不证明磁盘发布、桌面交互或跨平台通过。
- 宿主笔记文件的保存/打开接口：隔离真实目录中的候选校验、版本核对、旧版保留、安全发布、失败保全。它不证明 OneDrive 的双端传播。
- 真实桌面 UI→宿主→磁盘→重开：选库、三分区输入、手动保存、中文路径与同名不同身份的笔记。Windows 检查不替代 Mac 验收。

在每个接口上逐个执行失败测试→最小实现→通过测试。失效路径先使用隔离文件和可控制的系统操作失败，不改用户笔记或真实系统权限。功能实现后分别进行 Standards 与 Spec 审查。

## 格式权威与基本约定

Rust 中严格的 v1 类型及原生校验器是格式权威，生成 JSON Schema 与 TypeScript 声明并检查同步。JSON Schema 描述字段结构；各区允许节点、身份与引用关系、导图拓扑、图片内容及资源预算由原生校验器共同检查。仅通过 Schema 校验不代表整个笔记包有效。编辑器内部对象需适配到应用文档，不能直接成为未经验证的磁盘协议。

容器为 `.cuenote` ZIP，恰好包括 `document.json`、`assets/manifest.json` 和所引用的 `assets/<id>` 普通文件；只接受 Store/Deflate，无加密、跨卷、目录或路径别名。ID 使用小写 UUID v4。时间为带毫秒的 UTC `Z` 字符串，内容与组织修改时间分离。所有对象拒绝未知字段和重复键。

正文支持已批准的全部首版结构：段落、1–3 级标题、粗体/斜体/删除线、有序/无序/任务列表、引用、行内/块代码、链接、分隔线、基础表格、行内/块公式、图片和可编辑导图。线索区与总结区仅允许文字、粗体、列表和简单标题。公式保存原始 LaTeX，代码保存原始文本和语言标记。

导图保存扁平节点表、根 ID 及有序子节点 ID，验证单根、无环、每个非根节点仅有一个父节点、全体可达和 ID 唯一；节点文字与顺序保真。这样链状导图不会被当成深层 JSON。图片清单固定记录 ID、PNG/JPEG 媒体类型、长度、SHA-256 和原始尺寸，图片节点只保存资产 ID 与显示宽度；引用必须闭合，不接受本机路径或 blob URL。

当前 UI 只编辑纯文字段落。含已知富内容的有效 v1 文件可只读查看，其完整文档与资产保留在宿主；UI 与宿主同时阻止简易编辑器改写富内容。未知、缺图、损坏或未下载文件明确报错，不转为空白笔记。

`document.json` 的顶层字段固定为 `schemaVersion`、`noteId`、`title`、`sections`、`organization`、`timestamps`。`sections` 中的 `cue`、`content`、`summary` 各为内容块数组；组织信息包含可空的 `notebookId`、`pinned` 和可空的 `trashedAt`，时间包含 `createdAt`、`contentModifiedAt`、`organizationModifiedAt`。可空字段仍必须出现。块使用 `type` 判别，字段统一为 camelCase；标题为空不改变笔记身份。更高格式版本在进入 v1 结构校验前识别并拒绝。

笔记库将笔记放在 `notes/<笔记 ID>.cuenote`，每本笔记本单独存为 `notebooks/<笔记本 ID>.json`。笔记本元信息为 `schemaVersion`、`id`、`name`、`default`、`timestamps: { createdAt, modifiedAt }`。已有笔记而默认笔记本信息缺失时提示检查，不凭空生成新的默认归属。库内的错误文件和重复身份会显示提示；本阶段不合并或改写它们。

上次选择的库路径仅存在本机配置目录的独立设置快照中，不写入同步事实文件。默认位置为系统文档目录下的 `CueNote`；系统无法提供文档目录时，界面明确展示主目录下的 `Documents/CueNote` 建议位置，仍需用户选择并通过能力探针。正常发布构建不接受测试目录覆盖；调试构建的 `CUENOTE_TEST_ROOT` 仅用于显式隔离真实桌面验证。

## 固定资源预算

| 项目 | 上限 |
| --- | --- |
| 原生包文件 | 256 MiB |
| 全部条目实际展开总量 | 512 MiB |
| document.json | 64 MiB |
| assets/manifest.json | 16 MiB |
| JSON 嵌套深度 | 64 |
| ZIP 条目 | 8,194（至多 8,192 个资产） |
| 单张图片 | 25,000,000 像素 |
| 全部图片 | 100,000,000 像素 |
| 全部导图 | 5,000 节点 |

大小按实际流式读取计数，不按 ZIP 声明值分配无界内存。构造 ZIP 元数据对象前先检查有界目录；核实目录/本地条目匹配、唯一名称、CRC 和实际展开量。内部预算须容纳已确认的普通及压力样本，不以预算为由缩减规格。

## 界面与宿主

前端仅能请求选择/使用默认笔记库、在当前库新建/打开/保存笔记、打开已选目录。目录授权由 Rust 原生选择器或默认位置产生，不接受前端任意路径读写。文件路径、完整文档、资产和版本基线由宿主会话保存。

界面使用 `WorkspaceView`、`LibraryView`、`NoteSession` 和 `PlainNoteText`；当前保存命令只接收会话 ID 与四个文字字段。宿主设置身份、归属、时间和版本，不信任前端提交的元信息。保存返回的是该次快照；响应期间的新文字仍显示未保存。未保存编辑的切换需要明确处理；完整自动保存与关闭恢复由 #15 继续落实。

## 保存与失败

选库时使用独立探针验证创建、写入、同目录原子替换并清理自身探针。每次保存仍重新处理实际 I/O 错误：完整候选→同步→重读校验→版本核对→独立旧版保留→再次核对→平台安全发布。失败不得转成直接覆盖，也不得声称云端同步成功。

本机恢复区在库外保存验证过的旧版及失败草稿。保存失败时保留前端当前输入，说明恢复副本是否真正写入；恢复区失败也必须如实报告。新版或损坏的现存文件不得被空文档覆盖。具体平台失败语义遵循 [ReplaceFileW 官方说明](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew)，不能假设失败必然保持原文件名。
