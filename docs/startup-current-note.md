# 当前笔记优先的启动路径

Mac 的关闭追踪诊断复现首次重开超过 3000 ms。初始工作区先扫描全部源文件，会让当前笔记和首图等待。该改动先真实读取记忆中的当前笔记，独立保留其版本，再返回编辑会话；其它笔记由已有可中断检查继续验证和保留。

`Workspace::snapshot()` 保持完整扫描语义；只有桌面 `get_workspace` 使用新启动入口。首次初始化、健康笔记本元数据、有效可编辑且未删除的记忆笔记才走快速路径。恢复指针、共享访问租约和待完成发布恢复仍在前面执行。缺失、损坏、新版格式、身份不符、只读或版本保留失败回到原完整路径，不使用缓存中的旧内容授权编辑。

`LibraryView.scanState` 明确区分 `pending`、`complete`、`unavailable`。初始投影仅包含刚读取的当前笔记；计数不把它当成全库总数，搜索保持 Building，也不发布不完整的派生缓存。完整检查最终更新列表；编辑草稿及冲突处理继续使用会话和输入版本保护。保存时仍实读元数据、比较源版本，未完成索引不满足已保存笔记的快速投影条件。

连续输入不会阻止初次列表完成：检查结果仅在同一会话、同一库、尚未完成列表且未进入恢复时更新列表。正文、编辑权限及冲突处理仍须匹配输入版本；过期检查保留重试。已经更新的保存回执不会被此列表回调覆盖。

诊断原始记录见 [缩小启动复现](macos-startup-minimal-9760cf6.md)。该设计及本机回归不代表 Mac 已达 3 秒；仍须在相同固定样本、正常备份、关闭追踪条件下执行原始完整性能矩阵，核对首图、导图、最终索引与原生笔记内容。

本机验证：Rust 全量 292 项通过；随后新增一次启动调用及缓存保真断言，启动专项 12 项通过。前端最终 150 项通过，类型检查、生产构建、Rust 格式和格式 schema 校验通过。独立只读审查未发现阻断性问题；其连续输入导致初次列表延后的发现已复现并修复，新增七项前端边界测试。第一次保存若赶在完整检查之前仍执行完整扫描，这一延迟需在实机另测。
