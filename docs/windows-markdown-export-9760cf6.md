# Windows Markdown 导出实机验收（9760cf6）

Windows 单端 A22 通过。使用已安装普通候选的原生导出按钮和系统目录选择框，完成两次导出；移动导出目录后，在独立 Markdown 读取器中渲染并检查截图。Mac 对应用例尚未完成。

程序源码为 `9760cf6eb6f7ea353d94ec5f7ebd4c08aaceb50c`，二进制 SHA-256 为 `a4520e94a0807b7f45a2ed722bd7dbce92016342a312ca6480845002846e0919`。使用专用合成数据：一篇经普通界面另存入库的富内容笔记，以及一篇预先准备的 Q50 全格式库外笔记。预制样本只证明导出行为，不代替 Markdown 输入验收。

| 核验 | 结果 |
| --- | --- |
| 三分区与格式 | 标题、线索、内容和总结可读；标题级别、强调、删除线、引用、列表、任务列表、链接、表格、行内代码和分隔线保留。 |
| 代码与公式 | JavaScript、TypeScript、Python、Rust、C#、SQL、JSON 和未知语言的原文附件及围栏一致；行内/块公式的源文本、类型及美元转义一致。独立读取器的公式渲染能力另计。 |
| 图片与导图 | 原始图片字节一致；SVG 预览可读，节点原文 JSON 的身份和层级一致。导出文件明确说明静态预览不能在 Markdown 中继续编辑导图。 |
| 移动与原件 | 第一份 5 个文件、4 条相对附件引用；第二份 18 个文件、17 条引用。移动后全部哈希及引用正确，原导出位置已不存在，原生笔记包未改变。 |

独立读取使用 PowerShell 的 Markdig 转换和本地 Edge 渲染；没有借用 CueNote 的界面作为导出读取器。原始输出、移动后目录、核验回执和截图只保留本机，哈希见 [结构化结果](windows-markdown-export-9760cf6-results.json)。

此前 Listary 抢占对话框焦点导致输入安全停止；用户暂停 Listary 后完成导出。系统目录对话框异步关闭，以实际导出文件和成功状态为准。第一次附加样本因测试脚本转换时间戳产生无效格式，被程序正确拒绝；修正样本后才计入结果，失败样本及记录保留。
