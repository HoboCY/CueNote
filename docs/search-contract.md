# 搜索实现说明

任务与验收规格以 GitHub 上的 [#25](https://github.com/HoboCY/CueNote/issues/25)、[最终规格 A03、A25、A26](https://github.com/HoboCY/CueNote/issues/8#issuecomment-6165724793)及[整体技术方案](https://github.com/HoboCY/CueNote/issues/7#issuecomment-6164489548)为准。本文件仅记录当前实现及验证边界，不新增验收条件。笔记文件仍是事实来源，搜索只提供派生的查找结果。

## 范围与匹配

- 搜索当前笔记库的全部笔记，或当前选择的一个笔记本。普通结果不包含回收站、库外笔记、历史版本或恢复草稿。
- 搜索标题、线索区、内容区、总结区，以及其中的代码原文、公式 LaTeX 源文本和思维导图节点文字。图片像素和资产身份不参与搜索。
- 使用字面子串包含匹配，英文字母大小写不敏感。没有 OCR、模糊匹配、语义搜索或数学等价转换。同一段落中的相邻富文本和真实换行保持连续；段落、表格单元格及导图节点分别匹配，排版分隔符、图片占位符和列表标记不凭空变成可搜索内容。
- 一篇笔记最多出现一条结果。结果标明命中的标题或分区，摘要截取真实命中位置附近的原文；高亮不解析 HTML。结果沿用置顶、修改时间和身份的确定顺序，每页最多 100 篇。
- 空查询返回普通笔记列表；查询中的有效空格保持原样。单次查询最多 1,024 个 Unicode 字符，超出时明确提示。

搜索反映已保存的笔记内容。编辑中的新文字在保存成功后加入结果；搜索框本身不会替用户保存或放弃草稿。

## 索引与文件变化

首版在读取并验证笔记包的同一趟库扫描中建立本机内存索引，查询阶段不打开或解压笔记文件。索引不写入同步目录，也没有需要同步的数据库。退出应用即丢弃索引；重新打开笔记库或使用“重建搜索”从笔记文件重新生成。

保存、移动、移入回收站、恢复和外部文件刷新后，列表与索引采用同一次扫描的结果。库切换或文件变化使旧查询失效；前端丢弃过期响应，不能把旧库的命中显示在新库中。点击结果沿用打开笔记的保存与草稿保护流程。

目录暂不可用时，界面可以保留上次可见的笔记列表，搜索不会把旧索引当成当前结果。个别笔记尚未下载、格式不支持、无法验证或索引达到容量边界时，明确提示结果不完整。用户可处理文件后重新检查或重建搜索，不能把部分索引的零命中解释为完整库中不存在该内容。

扫描进度包含已检查文件数和总文件数；失败或跳过的文件也计入已检查数。进度不表示 OneDrive 已上传完成。索引原文及大小写匹配副本合计限制为 128 MiB，超过边界的笔记不会悄悄截断后作为完整内容参与查询。

## 验证边界

#25 使用固定混合语料及已知命中集合验证正确性，并记录本机局部查询耗时。千篇固定样本、启动、初次索引、查询至显示、内存及压力笔记的正式统计属于 [#31](https://github.com/HoboCY/CueNote/issues/31)。当前内存索引每次进程重启都需要重建；是否增加持久缓存，应由 #31 对现有库扫描的实测决定，同时保持缓存可删除、源文件可重建。

Windows 本机文件变化测试不等于真实 OneDrive 或 macOS 验收；双端日用结论仍属于 [#33](https://github.com/HoboCY/CueNote/issues/33)。
