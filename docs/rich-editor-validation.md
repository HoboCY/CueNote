`italic-hit-diagnostic2` 另复现了真实的快速格式化竞态：Shift+Home 选中文字后，可信鼠标点击在 388.7 ms 命中斜体按钮，浏览器 `selectionchange` 在 405.4 ms 才到达；编辑器使用旧折叠选区设置的输入格式随后被清掉，文字未变成斜体。等待选区同步后，同一按钮可正常格式化并保存。这项失败没有被归为普通脚本错误。

修复在工具栏命令和链接表单打开前，通过公开的 DOM 位置映射同步本编辑器的文本选区。已有 NodeSelection、CellSelection 和组合输入不进入这条同步路径。修复后再次通过类型检查、14 项前端测试和桌面构建，构建记录为 `desktop-build-selection-fix.log`。

## Standards 与 Spec

两位独立审查者检查了基线到固定树的差异。Standards 提出 `section` 与 `simple` 重复表达策略的低优先级问题，已改为由分区推导。Spec 发现回收站显示无法执行的“另存完整副本”按钮，已隐藏该入口；普通不支持编辑的只读笔记仍保留完整副本路径。两位审查者均复核了修正差异，未发现新增问题。

两位审查者也复核了快速格式化修正，未确认当前功能的新增缺陷。Standards 留下一项低优先级边界建议：公开 DOM 映射的默认 bias 与编辑器内部选区读取存在差异；后续引入图片、导图等原子节点或自定义选区时，应补查相邻结构边界。
