# 外部变化、保留版本与并发发布

对应 [开发任务 #23](https://github.com/HoboCY/CueNote/issues/23)。本项沿用原生格式版本 1、现有资源预算、库外恢复区及不自动合并的决定。

## 编辑会话

- 文件通知只请求核对。启动、重新聚焦和每次保存同样触发内容指纹核对；通知次数、顺序及文件名不能用作版本依据。保存同步核对当前笔记及笔记本元数据，完成安全发布和必要历史保留后可先返回当前笔记的列表与搜索投影；每次库内保存成功都主动安排随后完整核对，不依赖文件通知，也不因界面已切换会话而漏掉该请求。身份或索引不完整、组织信息变化及容量不足时继续使用同步完整扫描。
- `probe_external_changes` 不替换活动会话。发现变化后，界面暂停自动保存，等在途写入及编辑器输入结束，同步禁用编辑，再捕获最终草稿并调用 `reconcile_external_changes`。
- 干净会话先在独立恢复区保存已持有的旧版和取得的外部新版，再采用新会话。旧会话或过期核对结果不能覆盖当前输入。
- 有草稿、笔记身份变化、删除或暂不可读时，不自动刷新或合并。取得的有效版本分别保留，提供只读打开、恢复为新笔记、另存及标记已处理的入口；删除或读取错误不解释为空白笔记。
- 独立保护失败时不报告草稿已保存。用户可另存完整副本；编辑器收敛并等待在途写入后，只有该副本与当前会话和最终草稿精确匹配，才允许用户明确选择关闭或继续。取消关闭/切换会阻止旧操作继续，已发出的保护仍可完成；同一干净笔记的宿主会话刷新需同步，但不清除后来排队的操作。
- 扫描也保留已取得的有效版本。非标准文件名、同步冲突副本和重复身份的不同内容保留并提示；源文件不自动改名或删除。

## 独立保留版本

保留完整原生笔记，包含图片及可编辑导图。恢复副本可以重新编码，因此分别记录源文件指纹与恢复文件的实际指纹，不声称两者字节相同。记录来自同一次验证读取中的笔记包，不通过随后重读源路径冒充先前取得的版本。

普通版本按每篇笔记及来源保留最近 30 份；活动编辑基线持有租约，不能被其他实例的轮换删除。冲突版本不自动轮换。标记已处理仅改变待处理列表，不删除文件。恢复记录使用宿主验证的不透明标识，网页界面不能指定恢复区文件路径。

## 保存发布

保存先持久化本地草稿，再核对基线并发布。CueNote 实例通过文件锁协调；不遵守该锁的程序仍可能在最后一次指纹核对后写入。

发布操作必须留下被替换项：Windows 使用带唯一备份的 `ReplaceFileW`，macOS 使用同目录原子交换。发布前保存意图记录；发布后先验证并转存被替换项，再清理临时文件。被替换版本不同于基线时，目标可能已经是本地候选，但结果仍是冲突，不显示保存成功，不用旧版回滚覆盖更新的内容。启动时从意图记录找回中断留下的有效文件。

只有已确认发布、重读校验且独立版本已持久化后的清理故障，才可显示“已保存并有警告”。其他失败保持失败或冲突。所选目录不支持需要的操作时拒绝原地保存。

## 验证范围

预先约定的测试边界为公共 Workspace/存储接口与隔离真实文件、真实子进程故障注入、前端保存协调器的时钟/IPC，以及真实 Windows 桌面宿主。关键反例是在最后一次核对后注入外部 B，验证已持有的 A、外部 B 和本地 C 均可找回，且界面不报告保存成功；另验证发布原语返回后立即退出的恢复。

本项不宣称阻止任意程序通过已打开句柄持续原位改写，也不承诺恢复应用从未取得的远端版本。macOS 与真实 OneDrive 的端到端结果须由后续实机验收提供；本机测试不代替它们。

文件通知的可靠性限制参考 [notify 官方说明](https://docs.rs/notify/8.2.0/notify/)；发布语义参考 [Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) 与 [Apple APFS 安全保存 API](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/ToolsandAPIs/ToolsandAPIs.html)。验证结果另行记录，以上为实现契约。
