```powershell

cargo test --features storage-fault-injection --test storage_interruptions noncooperating_valid_write_after_final_hash_is_reported_as_conflict -- --nocapture
```

构建成功。使用 `save_note_content` 的纠正后回归测试失败，测试退出码 101：子进程退出码为 0，返回保存成功的 receipt；receipt 的警告文字同时包含 Windows 原子替换备份指纹不一致的冲突。这证明上层把真实冲突提升成了保存成功。

用例的正确要求是冲突返回，并且独立恢复区可重新读取 A、B、C。原子替换后目标可以已是 C；不要求把目标回滚到 B，以免再次覆盖更晚的外部更新。

完整回归的原 `save_failures` 夹具在重命名整个恢复目录时遇到 Windows `ERROR_ACCESS_DENIED`。独立 `target/testdata/rename_handle_probe.rs` 证明：打开其后代文件句柄即会导致失败，未加锁、共享锁和显式 `FILE_SHARE_DELETE` 都相同，关闭句柄后成功。活动版本租约需要该句柄，因此夹具改为只把 `recovery/drafts` 隔离并在原位放普通文件；仍验证库不可达、草稿保存/列表失败、安全另存成功、原件不变和拒绝覆盖。
