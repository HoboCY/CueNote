# 整库恢复中的 Windows 发布记录路径修复

普通 Windows `4f517a4` 在确认整库恢复后返回“发布恢复记录中的目标或候选路径不符合安全边界”。本机恢复区保留着另一专用测试库的合法未解决发布记录；当前库四个文件和原有十三个备份文件均未变化。

原因是整库恢复的公共检查先用普通路径构造记录目录，再规范化恢复根目录。Windows 规范化会加入 `\\?\` 前缀，随后记录父目录与安全校验根目录按不同形式比较，导致误拒绝。修复仅让枚举记录使用规范化后的目录；不跳过任何记录校验，也不删除旧记录。开始恢复、暂存后再检查、继续与回退的四处调用共享此修复。

真实恢复 API 的回归测试在修复前以同一 `unsafePath` 错误失败，测试本身耗时 0.19 秒。修复后 107 项相关原生测试通过，零失败、零跳过，格式检查通过。四项新增测试覆盖：其他库合法记录保持原字节并允许当前库恢复；当前库未解决记录仍阻止恢复；目录身份已变化仍拒绝；其他库不安全记录仍拒绝。

独立执行环境因依赖缓存缺失及下载错误未能完成测试，已停止该任务；以上红绿结果来自主代理使用本机既有缓存的离线执行。没有把工具环境失败计为产品失败。

修复候选 `3518441` 已在原 Windows 现场通过普通安装版复测：原生点击确认整库恢复后，从 3 篇笔记恢复为来源备份的 2 篇笔记、1 个笔记本。恢复前完整手动备份保存了新增笔记；来源及原有备份保持不变。通过正常关闭及 Explorer 重开，内容、图片和可编辑导图等内嵌资产仍与所选备份逐字节一致，界面解除操作锁定。三条导致原错误的其他库发布记录均保留原字节，没有通过清理记录避开问题。

本轮 109 项证据核对通过。恢复移出的旧文件按既有合同保留为隐藏工件，不计作原生笔记，也未被删除。结合已有双端原生故障用例及此前 Windows 普通版单篇恢复，Windows 单端 A20 通过；Mac 普通版整库执行仍待完成，因此双端 A20 不勾选。命令、安装来源和证据哈希见[结构化结果](restore-journal-path-fix-results.json)。
