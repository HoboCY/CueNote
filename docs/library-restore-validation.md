# 整库恢复验证

对应 [#28](https://github.com/HoboCY/CueNote/issues/28)、最终规格 A20 与[整库恢复约定](library-restore-contract.md)。使用隔离的合成笔记库、公开宿主接口和真实 Windows 桌面程序。

## 自动化覆盖

前端 133 项测试通过。整库恢复协调器覆盖先保存编辑内容、固定来源及清单版本、防止重复确认、取消请求与宿主结果的不同返回顺序，以及刷新失败时保留真实恢复回执。错误后根据宿主实际状态区分有待处理任务和无待处理任务。

Rust 的公开接口与真实文件测试覆盖完整原生集合、空笔记本、回收站、置顶、重复原生文件、资产、恢复前手动备份、来源改变、外部新增或第三版本、继续和回退，以及终态记录的方向和文件证据一致性。未取得写入意图的路径必须保持恢复前版本，不能把外部恰好到达的来源内容当成任务自己的写入。

故障子进程覆盖暂存、逐文件发布、日志半写、候选半写、完成记录和回退阶段的中断。只有来源已完整验证、原件未变、没有移出件且残片是来源严格前缀时才允许重新准备；残片仍保留。磁盘空间不足使用隔离故障注入，没有实际耗尽电脑磁盘。

2026-10-15，构建启用 `storage-fault-injection` 的故障 examples 后，执行完整 Rust 测试，217 项全部通过，0 失败、0 忽略。`cargo fmt --check`、`git diff --check` 和最终 `npm run build:desktop -- --debug` 通过，后者包含类型检查与前端构建。此前失败记录保留，最终 Rust 结果使用修复后的完整重跑。随后仅修改界面状态刷新与提示，逐文件 SHA 核对后端未变，复用有效 Rust 结果。

## 回归与复核

固定审查基线为 `019c1056bd94b75a6b038e0b89a88c52bf4c1119`，范围包括全部任务修改和新增文件。Spec 与 Standards 独立检查，修正内容包含中间态写入门禁、终态收尾验证、日志半写保留及回退方向一致性。

完整回归发现新增门禁过早返回，跳过了原有的缺库草稿保护。保存现在先构造候选，门禁失败只尝试本机草稿保护；明确另存副本使用缓存或保全版本，并保持库外路径限制和不覆盖发布。旧库缺失且没有未完成恢复记录时，仍可切换到健康库；恢复指针会在启动读取和目录缺失时继续阻止普通操作。Windows 扩展路径和显示路径使用同一库身份，目录联接测试实际创建夹具后验证拒绝，未以跳过代替通过。

另一完整回归复现缺库时遗漏“保留上次可见列表”告警。选中库根明确不存在时，先核对未完成恢复记录，再进入既有的缓存列表保留流程；其它原生操作继续严格检查。原有同步到达测试 6 项通过，没有缩小断言。

Standards 复核指出，原有的另存路径检查和发布会分别解析目标目录，无法保证恢复待处理时的库外导出边界。修复后共用保留目录句柄的目标：Windows 固定祖先目录，Unix 相对目录句柄创建候选并发布。Windows 定向测试验证固定句柄阻止祖先替换、正常副本可读及已有目标不被覆盖，2 项通过；缺库保存 3 项与同步到达 6 项也通过。首次普通沙箱运行的访问拒绝在允许该文件操作的执行环境中复测消失，没有据此改换 Windows API。Unix 分支尚未在对应平台编译或运行。

Spec 随后指出按名称清理失败候选可能删除其他进程替换的临时项。最终实现保留另存失败后的候选资料，报告创建时路径，并在目录变化时提示核对实际位置；不增加不可靠的自动删除。成功另存仍以无覆盖移动完成，不留下候选。两个桌面流程在首次输入前正常关闭了旧构建，保留启动与关闭记录，等待此修正后的程序。

## Windows 桌面验收

首次真实桌面尝试发现两个自动化尚未覆盖的连接问题：恢复写入自己的库标记会触发监听并取消任务；待恢复状态直接返回 Windows 扩展路径，导致界面与库视图的位置比较失败。现场原有 9 个原生文件及保护备份均逐字节一致。新增回归先复现上述两项及排队写入干扰恢复的竞态，共 3 项失败；修复后 25 项整库恢复与 11 项普通备份测试通过。文件监听与显式暂停现在分开处理，恢复任务和普通写操作在协调锁内互斥，状态 DTO 统一显示路径。

这次运行时修复的两项独立复核未能启动，DeepSeek 服务报告无法解密当前 Windows 用户的配置密钥；没有切换后端或声称取得独立通过结论。已有独立审查针对修复前的完整实现，新增改动由主代理按架构调查结论复核并执行回归与桌面重跑。

四个场景在不含故障注入功能的 build5 程序通过，SHA-256 为 `343047C3B78B4E8C4CBDE6546C0856D1BE6091A626973102F164A2F08CF78D51`。每个场景使用独立设置、恢复区、备份目录和 WebView 配置；输入使用已核对程序的实际鼠标和键盘事件，DOM 只读。核对完整原生文件路径、长度和 SHA-256，并验证保护备份、正常退出和重新启动。

## 验证边界

整库恢复通过持久化计划和逐文件操作继续或回退，不提供整个目录原子事务。本任务的本机锁不提供跨设备分布式锁。Mac、真实 OneDrive 和完整双端日用验收属于 #33；小型合成库不作为 #31 性能结论。
