# 整库恢复

对应 [#28](https://github.com/HoboCY/CueNote/issues/28)、最终规格 A20 与[可移植笔记文件决策](adr/0002-portable-note-files.md)。

## 范围与确认

从已校验的备份列表选择来源，预校验完整清单及全部原生文件，再明确确认替换范围。恢复将当前库的 `notes/*.cuenote`、`notebooks/*.json` 替换成来源备份的完整集合，包含库内重复原生文件、空笔记本、归属、置顶与回收站状态；其他文件和库外本机恢复区不在替换范围内。来源没有的当前原生文件会离开活动库。

确认前整理编辑器并保存最新草稿。宿主再次核对所选备份和清单版本，成功创建并验证当前库的完整手动备份；备份失败、来源改变或当前库在捕获期间改变，都不能进入原生文件写入。恢复前手动备份不参与自动轮换。

## 持久化进度

本机恢复区保存不可变计划、来源与恢复前两份完整暂存快照，以及逐文件的写入意图和完成记录。库根的 `.cuenote-restore.json` 与本机活动指针标记未完成任务。首次原生文件修改发生前，计划、快照和标记必须已经持久化。

记录先写入同目录临时文件并同步，之后才无覆盖发布为正式记录；半写残片保留，但不作为有效日志读取。未写完的事实候选仅在原件仍为预期版本、移出件不存在、候选是完整校验来源的严格前缀时允许重新准备；包括尚未写入任何字节的空候选。重新准备前保全残片，内容不符或原件变化则停止。

逐文件创建、替换或移出时核对前后 SHA-256；替换和移出保留实际旧文件。记录完成前再读取核对。此流程不提供整个目录的原子事务；中间状态需要由任务继续处理。普通编辑、备份、外部更新检查和旧单篇发布记录重放不能使用该中间状态。本机多个进程通过共享／独占库锁协调，库内标记只用于跨设备停止提示，不代表分布式锁。

## 暂停、重启与回退

取消请求在安全边界暂停，不能被描述为自动撤销已完成文件。重启发现标记或本机活动记录时，先显示恢复状态，停止普通库操作；用户选择继续或回退。继续会核验实际目标、候选、移出件及日志，不仅依赖计数。回退按反向次序恢复完整的恢复前原生集合；一旦开始回退，后续“继续”也是继续回退。

文件监听通知只作为普通备份的提前取消提示。整库恢复会产生自己的文件通知，因此恢复任务依靠各阶段的完整集合与版本核验识别外部变化，并继续响应用户的主动暂停请求。恢复任务注册与普通写操作准入使用同一个协调锁；排队写入不能误取消恢复。界面恢复状态使用与笔记库视图一致的显示路径，持久化计划仍保存规范化路径身份。

来源、保护快照、标记或日志缺失、损坏或身份不符时停止操作。出现第三个文件版本、意外增加／删除的原生文件时保留现场并报告冲突，不静默覆盖。已经完成且移除库标记的任务只做本机记录收尾，不把其后的正常外部修改重新回滚。

库门禁失败时，保存入口不发布原生文件，仍尝试保全当前输入的本机草稿，并返回草稿结果或失败原因。明确另存库外副本时，只使用缓存会话或已保全的恢复版本，不依赖当前库可读，也不扫描恢复中间态。副本的库外边界检查与发布共用固定目录身份，不能通过再次解析路径绕过边界，也不覆盖已存在的目标。旧库不可达且没有未完成恢复记录时，仍能选择健康的笔记库；未完成记录不能通过改名或移走库目录绕过。

原生集合核验完成后记录终态并移除标记、活动指针，再重新读取库、清空旧编辑会话并重建派生索引。文件已经完成而索引或设置刷新失败时，错误必须明确说明文件结果及恢复前备份位置。来源、手动保护备份及恢复日志作为证据保留；不在本任务自动清理恢复材料。

验证使用隔离真实文件、公开宿主接口、故障子进程和 Windows 桌面。Mac、真实 OneDrive 及双端日用结论由 #33 汇总。
