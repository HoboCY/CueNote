# 图片实现契约（#21）

依据 [#21](https://github.com/HoboCY/CueNote/issues/21) 和首版最终规格 A07/A10/A23。沿用原生 v1 的 `image { assetId, displayWidthPx }`，图片只出现在内容区的顶层。线索与总结维持精简排版。

## 编辑与粘贴

接受剪贴板提供的 PNG/JPEG 原始文件；系统位图以剪贴板提供的 PNG 保存。保存原始资产字节，等比缩放只改变显示宽度。明确拒绝不支持的格式，不创建空图片块，也不加载粘贴 HTML 中的远程图片。

图片插在当前段落之后，保留选中文字。光标在列表、引用或表格时，放在该顶层内容块之后，并说明插入位置。图片前后可以继续输入；移动、删除和调整尺寸参加内容区历史。预览 URL 属于当前视图，不进入编辑器内容、原生文档或恢复草稿。

图片解码及保存预算预检在异步宿主调用中完成。等待期间继续编辑时，映射原插入位置，用最新三分区草稿重新检查；只有编辑器文档和完整草稿仍与检查时一致，才同步提交这一笔插入。已删除的目标或离开的会话不能接收迟到的结果。切换、关闭和手动保存等待已经开始的粘贴，再保存最新草稿。

## 资产与文件

Rust 决定媒体类型、尺寸、资产 UUID 和 SHA-256，前端只能用当前会话标识及资产标识访问图片。原始字节使用二进制 IPC，不经 JSON 数字数组。每个候选包只包含当前正文引用的资产，引用、清单和 ZIP 条目必须闭合。

新图片和删除后仍可能撤销的旧图片暂存于本机、会话私有的磁盘目录，避免无限累积常驻内存。正常离开会话时释放；异常遗留只在确认对应运行目录没有活动持有者后清理。暂存失败不得发布会丢失撤销所需资产的保存。恢复草稿仍是自包含的完整原生文件，不依赖暂存目录。

插入预检、保存和解析遵守同一预算：单图不超过 25,000,000 像素，整篇唯一资产合计不超过 100,000,000 像素；原生压缩包不超过 256 MiB，实际展开总量不超过 512 MiB，并遵守既有文档、清单、深度和条目数量限制。完整候选内容通过同一 ZIP 写入逻辑检查实际包大小。拒绝插入时保留已有草稿，不以临时内存限制缩小文件格式支持范围。

## 验证边界

沿用已确认的公开边界：

- 模型转换与真实编辑器事务：合法位置、顺序、尺寸、撤销重做、异步打字和拒绝插入后的内容。
- 公开 Workspace 与真实隔离文件：原始资产、完整包保存重开、另存及恢复、删除保存后的撤销，以及预算边界。
- Windows 原生窗口、真实系统剪贴板和真实文件：图片来源关闭后重开、预览、缩放移动和正常退出。合成 ClipboardEvent、程序写入系统剪贴板、真实来源应用复制分别记录，不相互替代。

macOS 与真实 OneDrive 双端日用由 #33 汇总。本契约描述实施及验收要求；实测结果另行记录。
