# M1 首次重启超时诊断

2026-10-18，`cf350d8` 的[第八轮完整矩阵](performance-macos-matrix8.md)仅启动门槛失败。下面的额外运行独立留档，不替换正式慢样本，也不计入 Q51 成绩。

在矩阵已使用的 `index-1` 库上，使用相同二进制、原生启动/图片滚动/双帧终点及正常关闭路径，关闭追踪连续重启 10 次。第一次为 3738.12 ms，其余九次为 1760.84–2035.80 ms，复现了正式矩阵的首次慢启动。未编辑笔记、未清理系统缓存或关闭自动备份。

随后单独启用既有 Rust 追踪，并在派生测试驱动中记录进程创建、观测端点、激活、文档聚焦及最终就绪边界，再正常重启五次。第一轮 3472.79 ms，其余 1895.33–2222.82 ms。该批追踪会带来额外开销，只用于区分路径。

追踪中的后台核对持有工作区锁，慢样本另一个编辑器命令在此等待约 865 ms。实际启动调用链中，后台核对与图片资产读取共用 `editor_work`；图片节点进入视口后才发起 `read_image_asset`。这是图片读取被后台扫描阻挡的具体机制证据，但当前通用追踪标签未单独标识该等待命令的名字，仍需命令层并发回归及同机修复前后对照确认。首次快照本身也比后续慢约 0.4 秒，不能把所有首次成本都归于锁等待。

原有后台扫描已为前台保存提供安全让路与重试边界。修复提交 `9760cf6` 将同一优先权用于可见图片读取：在阻塞任务内、等待工作区锁前登记意图，并在任务结束或报错时释放。读取仍保留恢复、会话、目录和占位文件保护，不进入备份写入门禁，也不取消备份；后台核对沿用安全让路与重试边界。

命令层回归先在旧实现失败（预期后台核对让路，实际完成扫描），加入优先权后通过。真实图片读取返回原始字节、失败释放优先权、恢复期间拒绝访问及备份不被取消均有回归；完整原生测试 245/245、格式检查和文件格式定义检查通过。规范审查没有硬性违规，提出三项低优先级命名/组织建议；规格审查没有确认的实现缺陷，另指出调用者取消的直接测试及持续图片流公平性尚无运行证据。优先权持有者位于阻塞任务内部，取消等待不会提前释放它。

新构建的[第十轮完整矩阵](performance-macos-matrix10.md)仍有两次启动超时：4590.58 / 4101.88 ms。首张图片滚动后到最终就绪仅为 43.82 / 61.16 ms；启动总时间中，在进入就绪等待循环之前分别已消耗约 2475 / 1857 ms。新优先权没有解决完整启动门槛，也不能把剩余耗时继续归因于同一个图片锁等待。
