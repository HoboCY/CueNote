# 同步文件本机验证记录

## 行为与回归

- 笔记先到、笔记本元数据后到：原归属和置顶不变，后到信息补齐后可继续编辑。此前刷新无法发现后到元数据的回归先失败，再通过。
- 默认元数据缺失时保留选中的库和可读笔记，不隐式创建另一默认身份。已有空目录须明确初始化；含笔记、其他内容或无效元数据的目录不能按空库初始化。
- 整库或笔记目录暂缺保留可见列表、原会话和草稿；检查结果是不可读，与目录可用但单篇文件确已删除的状态区分。目录恢复后可以重新核对。
- Windows 隔离普通文件的 `OFFLINE` 属性模拟：打开和保存均拒绝，原文件字节不变；Workspace 保存失败保留完整草稿，恢复可读后可继续保存。此前打开错误接受该文件的回归先失败，再通过。
- 归属、置顶、回收站、空笔记本通过文件在两个隔离 Workspace 间体现；界面偏好留在各自设置目录。坏元数据、重名文件和重复身份的差异均保留并提示；不同身份的同名笔记本分别显示身份短码。
- 仅元数据的只读变化不替换正文草稿或撤销历史；中文组合输入、异步编辑或展开导图尚未收拢时延后更新只读状态。默认本缺失但已有其他有效笔记本时，回收站仍可显式选择恢复目标。
- 笔记本改名、删除使用用户已看到的版本作为基线。最终检查后外部替换、系统操作后外部再次替换、系统操作后进程退出，分别覆盖改名和删除，共 6 个独立进程用例。实际移出版本与本次改名请求有可扫描 JSON 保留文件；删除检测到原路径重现时报告冲突。新增竞态均先复现失败再验证修复。Windows 的旧问题包含外部版本留在不可扫描临时文件中；没有把 Unix 分支的静态风险写成 Windows 实测结果。
- 回收站永久删除先隔离实际包，再核验身份、版本和回收站状态。新增 3 个进程用例覆盖最终检查后换入新版、隔离后原路径重现、隔离后进程退出并从公开保留版本入口找回。旧实现把新版误删且返回成功的用例先失败，修复后通过；既有回收站 11 项同时通过。
