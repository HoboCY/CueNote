# 待办 Markdown 输入层级修复

在 `079fa6e` 普通 Windows 安装版的真实键盘验收中，从根段落逐字输入 `- [ ] 待办`，原生文件出现 `bulletList > listItem > taskList`。两次 Enter 后再输入引用和分隔线，它们仍落在外层无序列表中；截图和原生文件一致。这违反界面中 `- [ ]` 待办输入的预期，尚未计入 A06 通过。

原因在输入规则衔接：`- ` 先生成无序列表，随后 `[ ] ` 的上游规则在已有列表项内部包装任务列表。原生格式允许这种嵌套，因此保存转换没有报错；它不是保存遗漏。

修复仅在任务输入规则命中无序列表项的单一段落开头时，将当前项转换为同层任务列表。前后无序列表项分别保留，嵌套父级和段落内容不变。沿用上游规则的匹配范围和 checked 判定，其余结构继续使用原规则；编号列表和本来包含多个块的列表项不作自动扁平化。原生格式、转换器及保存流程未变。

新增回归通过真实 Tiptap 输入处理器逐字重放：最小待办及后续引用/分隔线两个测试在修复前均失败。修复后覆盖三分区使用的两类扩展、已选中/未选中标记、根级直接输入、前后列表项、嵌套父级、已有文字和加粗标记、普通/编号列表退出、输入规则撤销及工具栏切换。9 项列表回归、完整前端 **159/159**、TypeScript 与 Vite 构建均通过。撤销测试使用编辑器实际注册的同一组插件，避免重新创建插件导致测试读不到撤销状态。

独立静态审查确认位置计算、内容转移及撤销可逆性；提出匹配范围差异后，已改为复用上游匹配器并补充相关标记样本。审查没有运行桌面或输入法；最终匹配器调整由主执行人测试验证，不称为审查者复验通过。
