# CueNote 技术样机（抛弃式）

验证问题：[Tauri 技术样机能否满足 CueNote 的编辑与文件保存规则？](https://github.com/HoboCY/CueNote/issues/11)

本分支只用于选择技术路线。沿用已选 A 康奈尔布局，组合真实 Tiptap、Mind Elixir 与 Tauri/Rust 文件服务。没有完整笔记库、搜索、备份轮换或正式发行能力。

## 运行

安装依赖后，在仓库根目录运行：

```text
npm run setup
npm run prototype
```

浏览器访问 `http://127.0.0.1:4174`。此模式仅在内存编辑，刷新会丢失内容；桌面文件按钮不可用。

具备 Rust、平台编译工具和 WebView 后，可运行桌面样机：

```text
npm run desktop
```

无需开发服务器的本机调试版：

```text
npm run build:desktop -- --debug
npm run desktop:preview
```

启动器只为子进程设置样机路径：仓库下 `.scratch/PROTOTYPE-wipe-me`。不修改系统环境变量，不写入正式笔记库。不要同时运行多个样机实例。

Windows 需要 C++ 构建工具和 Windows SDK；macOS 需要 Xcode 命令行工具。参见 [Tauri 开发前置条件](https://v2.tauri.app/start/prerequisites/)。

## 试用顺序

1. 分别在线索区、内容区、总结区输入中文；在各区撤销，观察其他区内容是否保持。
2. 在正文使用 Markdown 输入规则，例如段落开头输入 `## ` 或 `- `；试用粗体和列表。
3. 在正文粘贴图片，调整显示宽度，确认比例和文字位置。真实系统剪贴板必须单独人工检查。
4. 插入并展开导图，修改节点、增加子节点和调整层级；关闭后确认预览更新，随后撤销正文变更。
5. 收起、展开笔记本栏，确认编辑内容不变。
6. 在桌面模式保存并重新打开，确认标题、三个分区、图片和可编辑导图恢复。
7. 使用样机的外部修改模拟，随后保存本机草稿，确认提示冲突且未静默覆盖磁盘文件。

## 保存边界

通过上述启动器运行时，桌面模式只读写仓库下 `.scratch/PROTOTYPE-wipe-me` 样机区域。不要把真实笔记交给样机。它采用手动保存，关闭前需点击“保存笔记”。

直接运行可执行文件且未设置 `CUENOTE_PROTOTYPE_SCRATCH_DIR` 时，才使用应用本地数据目录。此机器的 AppData 目录带加密属性，实际同目录原子更名/替换失败；该兼容问题尚未解决。请使用上述启动器。本次未更改系统加密/权限，也没有降级为非原子的覆盖写入。覆盖路径必须是绝对路径、最后一层为 `PROTOTYPE-wipe-me`，且不含 `..`。

`.cuenote` 使用 ZIP 包保存结构化内容与图片；图片在包内使用稳定引用。这个包结构是验证用草案，尚未成为首版文件格式规范。样机记录本机版本指纹以发现外部变化；这不能提供跨设备锁，也不能替代 OneDrive 双端验收。
